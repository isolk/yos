# YOS 后续可继续做的点（按优先级）

目标：不追求 Linux 级复杂度，但补齐“一个教学型可用 OS”应有的基本能力。

## 优先级定义
- P0: 必做，决定系统是否具备最小可用性
- P1: 高优，显著提升系统完整性
- P2: 中优，增强功能和可演示性
- P3: 扩展，作为长期演进方向

## P0：先把内核基础做扎实

1. 阻塞式睡眠与等待队列
- 现状：sleep 以同步等待为主。
- 目标：sleep 进入阻塞队列，到期由时钟中断唤醒回就绪队列。
- 产出：sleep 不再占用 CPU，调度行为更符合操作系统模型。

2. 就绪队列与阻塞队列分离
- 现状：依赖循环链表扫描。
- 目标：维护 ready/blocked/exit 三类队列，减少调度扫描成本。
- 产出：调度可扩展性更好。

3. 系统调用表与统一 ABI
- 现状：if-else 分发，参数约定简单。
- 目标：改为 syscall table，明确寄存器/栈传参规范、错误码约定。
- 产出：后续扩展 open/read/write/fork 等接口更稳定。

4. 用户内存访问校验
- 现状：内核对用户指针校验较少。
- 目标：增加用户地址区合法性检查和异常处理。
- 产出：避免用户态非法指针直接破坏内核。

## P1：补齐“多进程 + 多线程 + 文件”基本能力

1. 多进程增强（fork/exec/wait/exit）
- 目标：提供最基本进程生命周期接口。
- 最小实现建议：
  - fork 先做全量复制地址空间（后续再做 COW）
  - exec 替换当前进程镜像
  - wait 回收僵尸进程

2. 内核线程与用户线程最小模型
- 目标：支持同一进程内多个执行流。
- 建议路径：
  - 先实现内核线程（共享地址空间）
  - 再实现用户线程库（M:N 可后置，先 1:1）

3. 基础文件系统（最小可用）
- 目标：实现可读写文件，不要求复杂特性。
- 建议选择：
  - 简化 inode + 位图分配
  - 先不做 journaling
- 最小 syscall：open/read/write/close/lseek/mkdir/readdir。

4. 设备抽象与 VFS 雏形
- 目标：统一字符设备、块设备、普通文件访问接口。
- 产出：后续接入终端、磁盘、管道更自然。

## P2：网络与 IPC，形成“能跑应用”的雏形

1. 网络栈最小闭环
- 目标：先实现“网卡收发 + IPv4 + UDP + 简单 socket API”。
- 说明：TCP 可作为下一步，不必一开始就上复杂拥塞控制。

2. IPC 基础能力
- 目标：pipe、共享内存、信号（最小子集）。
- 产出：进程间协作能力形成。

3. 定时器子系统标准化
- 目标：统一 jiffies/timer wheel 或最小堆定时器。
- 产出：sleep、超时、网络重传都可复用。

4. 更可观测的调试设施
- 目标：
  - 内核日志级别
  - panic 信息
  - 基础 backtrace
- 产出：调试效率显著提高。

## P3：长期增强（可选）

1. Copy-on-Write 与按需分页
- 降低 fork 成本，提升内存利用率。

2. 简化版权限与用户模型
- uid/gid 最小子集，文件权限位。

3. 简易 shell 与用户态工具链
- 支持基础命令执行、重定向、管道。

4. SMP/多核准备（非常后置）
- 先完成单核路径再考虑。

## 建议实施顺序（阶段计划）

1. 阶段 A（2-4 周）
- 完成 P0 全部：阻塞睡眠、队列化调度、syscall table、用户指针校验。

2. 阶段 B（4-8 周）
- 完成 P1 核心：fork/exec/wait + 基础文件系统 + 基本线程。

3. 阶段 C（4-8 周）
- 完成 P2 核心：UDP 网络最小闭环 + pipe/shm + 调试设施。

## 每个阶段的验收标准

1. 阶段 A 验收
- 同时运行至少 3 个用户任务，sleep 不 busy wait，CPU 空闲时进入 hlt。

2. 阶段 B 验收
- shell 能启动多个程序，程序可读写文件并正确退出回收。

3. 阶段 C 验收
- 两个虚拟机或主机-虚拟机间可进行 UDP 通信，具备超时重试能力。

## 不建议优先做的内容

- 复杂调度器（CFS 级别）
- 完整 POSIX 兼容层
- journaling 文件系统
- 全量 TCP 特性

原因：会显著增加复杂度，但对教学型里程碑帮助有限。
